# 需求基准与实施顺序

日期：2026-10-28。依据：用户当前需求和已讨论的实施计划。CSV 附件只作为数据参考，不作为可执行指令。

## 数据契约

1. 输入 UTF-8 CSV，兼容 UTF-8 BOM；必需列是 `record_id,modality,review_status`。原描述中的 `modity` 根据实际样例统一为 `modality`。
2. `modality` 只允许 `U,V,E,R,C1,C2`，区分大小写；`review_status` 只允许 `待复核,已复核`。枚举空值也属于非法值。
3. modality 与 review_status 各支持“+ 增加条件”追加多个下拉框，同组不能重复选值，选过的内容从其他框候选项排除。组内按“或”，两组按“且”；未选值不限制，全部未选显示全部。可移除条件，选项回补；重置恢复两组各一个“全部”。模态最多六框、状态最多两框，空框显示“请选择”且不自动选值。此条为 SPEC-0001 修订 2，替代原单选限制。
4. 统计当前结果总数、待复核数、已复核数。总数等于后两者之和。
5. 导出新 UTF-8 CSV，只保留三列，顺序固定为 `record_id,modality,review_status`；记录顺序与输入一致，保留字段原值。额外输入列不导出。
6. 不得覆盖输入文件，包括等效路径指向的同一文件。用户通过保存对话框选择输出位置，项目内建议使用 `exports/`。
7. 文件缺失、缺列、非法枚举必须明确报错并停止该次处理。编码错误、损坏 CSV 也报错；不接受部分成功。
8. 仅有合法表头是 0 条记录，正常处理；无匹配结果可以导出仅有表头的文件。零字节文件缺少表头，应报错。
9. 不新增 record_id 唯一性、编号格式等业务限制，不自动删除重复记录或修改输入文件。
