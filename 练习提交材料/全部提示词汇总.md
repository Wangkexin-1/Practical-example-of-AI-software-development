### P-01 初始需求与计划

> 我需要你来辅助开发一个检测记录查询的小工具。现在我来提出任务：功能要求1.从UTF-8编码的CSV读取record_id，modity，review_status三列。modality允许UVERC1C2;review_status允许待复核，已复核。2.支持按modality、review_status单项或组合筛选，两个条件同时使用时按且匹配；未选条件时，显示全部。统计筛选结果的总数、待复核数和已复核数。3.将筛选结果导出为新csv，博阿留表头和上述三列；不得覆盖输入文件。文件缺失、缺列或枚举值非法时应明确报错并停止该次处理；仅有表头时按0条记录正常处理。以上就是功能要求，其实就是一个表格筛选软件，输入csv文档，输出筛选后的csv文档。具体的格式和筛选方式功能要求中都有。所以你需要完成这个，并自己根据我提供的样例生成一些数据进行测试，完全正确了才能验收。你先给出实施计划。

解释记录：原话中的 `modity` 根据原 CSV 表头统一为 `modality`；枚举拆分为 U、V、E、R、C1、C2。原话中的笔误按原样保留。最终多选行为由 P-04 修订。

## 二、可复用执行提示词（交付时整理）

### E-01 工程准备

在桌面独立目录建立本地 Git 仓库，不触碰其他项目。保留原 CSV 的逐字节副本，生成覆盖六种 modality、两种 review_status、空表、BOM、引号字段、缺列、非法枚举、错误编码与损坏 CSV 的样例。准备独立于应用实现的固定 ID/统计预期与 SHA-256 清单。用 Python 标准库和 Tkinter，无第三方运行依赖；提供环境检查、样例检查、运行说明，标明产品尚未实现时的 NOT_RUN 范围。

### E-02 从数据契约实现桌面工具

先写功能说明书及 AV/FU/UI 档案。数据流为外部 CSV → 全文件严格校验 → 不可变 Record 元组 → QuerySession 权威状态 → Result → 表格/统计或新 CSV。三列均为字符串；枚举精确匹配，不自动修改值、不去重记录。保留额外输入列兼容，但导出仅三列。失败导入清空旧会话，取消选择保留旧会话。仅表头合法，零字节非法。导出用 csv.writer 和 UTF-8 BOM，规范路径/文件身份识别同源，采用独占创建，不覆盖任何已有文件；写失败清理本次新建的不完整文件。提供 main.py 与可双击 .cmd 入口，实际启动。测试包括固定预期、错误输入、往返、链接保护及 Tk 控件集成；不把控件调用或截图冒充人工原生验收。

### E-03 多值筛选修订

沿 Record → QuerySession 条件 → Result → UI/导出的链路，定位单值条件限制，先修订原说明书与全部读写者。将两组条件升级为去重、枚举顺序的 tuple[str,...] 或 None，兼容旧单字符串调用；两组先校验后原子写回。组内 OR、组间 AND，空集合不限。两组各增加动态 FilterGroup：增加框默认“请选择”，排除本组其他框已选值，允许更换、移除和回补；最多六/两个框。普通刷新保留空白草稿行，重置、重导入或失败恢复各一框“全部”。导出必须仍从 Result 读取。验证全部 64×4=256 种子集、原 42 组预期、动态候选与生命周期、导出保真及最大行数布局。保留旧报告并追加本次结论。

### E-04 练习版本交付

检查 Git 干净状态和现有标签，使用 SemVer 练习预发布版本 0.1.0-practice.1，登记 VERSION 与 CHANGELOG。整理关键用户提示词、最终执行提示词、发布说明、可复现测试和运行步骤。对候选版本运行约定测试及可见窗口自动演示，独立核验导出结果，保存日志和截图，明确人工/原生输入验收边界。提交全部源码与资料后在 main 建立 annotated tag v0.1.0-practice.1，不移动已有标签。由标签生成源码 ZIP、本地 Git bundle、发布清单与 SHA256SUMS；解压/恢复后核对标签、字节和测试，保留双击运行及演示入口。本地仓库无远程时不配置或推送远程。
